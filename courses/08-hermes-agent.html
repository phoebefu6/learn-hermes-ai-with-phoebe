Part 1 · covers the Hermes Agent docs + GitHub README

The other Hermes 6 min live

Session 1's warning finally pays off. Hermes the MODEL family is what you have been running since Session 2. Hermes the AGENT, released February 25, 2026, is a different product wearing the same brand: an autonomous agent framework that can drive any capable model - including the one already on your laptop.

LiveModel vs agent - the distinction that matters3 min▶

A model answers. An agent acts. Hermes Agent is a desktop app (macOS 12+, Windows, Linux) plus a server backend, with a CLI/TUI for terminal people. It wraps ANY capable model - a Hermes, or something else entirely - in the machinery of autonomy:

  • Persistent memory. It remembers across sessions. Close it Tuesday, and Thursday it still knows your project.
  • Auto-generated skills. When it figures out how to do something, it writes the procedure down and reuses it. It genuinely improves with use.
  • Hands and senses. Browser automation, vision, image generation, text to speech, cron-style scheduling, and subagent delegation for parallel work.

The brain is pluggable: subscribe to Nous Portal for 300+ hosted models, or - our path - point it at the local model you already own. Same brand as the model family, different product. If a headline says "Hermes did X autonomously", it means the agent, not the weights you pulled in Session 2.

Why it exploded Released open source under the MIT license on February 25, 2026, it became one of the fastest-growing open projects ever - six figures of GitHub stars within months. The recipe: fully open, model-agnostic (bring your own brain), and it meets you on the channels you already live in.
LiveYour local model as the brain - and its honest limits3 min▶

The official local guide is exactly the stack you built: install Ollama, run hermes setup, choose Custom Endpoint, point at http://localhost:11434/v1. You did the hard part weeks ago.

One thing changes: context. You know num_ctx from Session 2 - your custom model runs 16,384. Agents burn context fast: every tool call, file read, and plan revision piles into the window, and when it overflows the agent "goes senile" mid-task, forgetting what it was doing. The guide recommends 64K or more for serious agent work.

  • The honest math: Hermes 4 14B tops out at 40,960 context. Even fully raised, that is a modest agent brain - fine for learning, short tasks, and tonight's demos.
  • Upgrade path 1: a bigger local model with a larger window, when your RAM allows.
  • Upgrade path 2: Nous Portal - OAuth sign-in, refresh token stored at ~/.hermes/auth.json, subscription tiers (a free tier with small monthly credits exists) bundling model access plus the Tool Gateway.
Real world

Proof of range. The ecosystem is already building on top: hermes-agent-self-evolution explores DSPy/GEPA self-optimization of the agent, and autonovel is an autonomous novel-writing pipeline that runs entire books through it. Your Friday folder summary is the shallow end of a very deep pool.

Part 2 · covers the Hermes Agent feature docs

Skills, memory, channels 6 min live

Three features turn a chatbot-with-tools into something that compounds: it learns procedures, it remembers you, and it is one identity everywhere you are.

LiveThe self-improving loop and persistent memory3 min▶

The first time you ask for something, the agent reasons its way through. Then it does something models never do: it writes down the procedure as a reusable skill. Next time, it loads the skill instead of rediscovering the wheel - faster, cheaper, more consistent. Skills accumulate into a private playbook shaped by your actual work.

Memory is the second compounding asset. Preferences, project context, past decisions - all persist across sessions. Together they change the economics: a chatbot resets to zero every morning; an agent appreciates.

Both live on YOUR machine in our setup - which cuts both ways, as Part 3 will insist.

LiveOne identity, every channel - plus a calendar and helpers3 min▶

Your agent is ONE identity reachable from Telegram, Discord, Slack, WhatsApp, Signal, Email, and the CLI. Message it from your phone on the train; it is the same agent, same memory, same skills as the desktop app at home. No per-channel clones.

  • Scheduling: cron-style timed jobs - "every Friday at 4pm, do X" - no human trigger needed.
  • Subagents: it can delegate pieces of a big task to helper agents and gather the results.
  • Senses: browser automation for the web, vision for images and screenshots, image generation and TTS for output.

Self-studyWhere the boundaries are2 min read▶

Calibration, so week one does not disappoint:

  • It is bounded by its brain. On a 14B with a modest window it handles short, well-scoped tasks well and sprawling multi-hour missions poorly. Match the task to the brain.
  • Skills are procedures, not magic. A saved skill for a job it did badly is a fast way to do the job badly again. Review what it saves (Demo 2 shows you how).
  • Channels need setup. Each messaging platform requires its own connection step - do the CLI and desktop first, add one channel you actually use, ignore the rest.
Part 3 · the responsible-adult card of the whole course

The safety conversation 5 min live

In Session 1 you accepted a deal: the model obeys you, and you own the responsibility. An autonomous agent raises the stakes on that same deal - because now the thing that obeys you also has hands. Files, terminal, browser, messages. This is not a reason for fear; it is a reason for house rules.

LiveThe five house rules4 min▶

Autonomy means real permissions on a real machine. Five rules, in force from your first run tonight:

RuleWhat it means in practice
1 · Sandbox firstStart in the most isolated execution backend you can - Docker is the sweet spot on a laptop. The agent works inside a container, not loose on your disk.
2 · Allowlist toolsEnable only the tools a job needs. A folder-summary agent does not need browser automation or shell access. Widen deliberately, never by default.
3 · No credentials in promptsNever paste passwords, API keys, or tokens into a conversation. The agent remembers, logs, and may echo. Use proper credential stores; keep secrets out of the transcript.
4 · Watch the first runsNew task type? Sit with it. Read what it plans, watch what it touches. Trust is earned per task, not granted per install.
5 · Confirm destructive and outward actionsDeleting, overwriting, sending anything to another human - require your explicit yes. An unsent draft is a fix; a sent email is an incident.

And a sixth that is really a mindset: memory is sensitive data. Everything the agent saw - file contents, names, half-finished plans - lives in its memory store. Treat that store like a confidential notebook: know where it lives, back it up deliberately, wipe it when you retire a machine.

Self-studyWhy this is calm, not scary2 min read▶

Every rule above is the same discipline any competent team applies to a new hire with system access: least privilege, supervised onboarding, no shared passwords, sign-off on irreversible actions. Nothing exotic - just applied to software that works while you sleep.

The payoff for doing it right is the whole promise of this course: an assistant that acts for you, on your machine, under your rules, with your data never leaving the room. The five rules are not the price of autonomy. They are what makes it yours.

The graduation - your model becomes an agent ★ 14 min · everyone follows

Eight sessions of preparation converge on ten minutes of setup. We install Hermes Agent, point it at the hermes4-14b-16k you built in Session 2, and hand it its first real job.

Install the Hermes Agent desktop app from hermes-agent.nousresearch.com (macOS 12+, Windows, Linux). Make sure Ollama is running in the background - it has been since Session 2.

Run hermes setup. When asked for a provider, choose Custom Endpoint and point it at http://localhost:11434/v1 - your local Ollama's OpenAI-compatible door, the same one your Session 5 pipeline used.

Select hermes4-14b-16k as the model - your custom build, constitution and 16K window included. Note the guide's warning: agents want 64K+ context or they go senile mid-task. Ours is modest; we keep tasks short on purpose.

First conversation: say hello, then run the "Try it now" inventory prompt from Part 2. Confirm it sees your backends and has zero skills saved. It is a newborn.

The first real task: point it at the demo notes folder and run the delegation prompt below. Then do the most important thing tonight - watch it work. Plan, file reads, draft, result. House rule 4, live.

Debrief honestly: it worked, and you saw the seams - a 14B brain on a small window thinks in short strides. Remember the two upgrade paths: a bigger local model, or Portal for hosted brains. The architecture you built tonight stays the same for both.

★ The first delegationIn the folder ~/hermes-course/notes there are 12 markdown files of my course notes. Read them all and write ONE file, SUMMARY.md, in the same folder: key ideas grouped by theme, then a 10-line "what I actually learned" section. Do not modify or delete any existing file. Show me your plan before you write anything.
If setup fights you Endpoint unreachable? Check Ollama is serving (ollama list responds). Model not found? The name must match your custom model exactly: hermes4-14b-16k. Agent rambles or stalls mid-task? That is the context ceiling talking - shrink the task, or revisit num_ctx from Session 2.
Demo 2 of 2

Teach it one skill ★ 6 min · build your own

A task done once is a favor. A task saved as a skill and scheduled is an employee. We turn Demo 1's summary job into a standing weekly routine - and then read what the agent wrote down about us.

Ask the agent to generalize what it just did: run the skill-teaching prompt below. Watch it save the procedure as a named skill.

Schedule it: "Run the weekly-notes-summary skill every Friday at 4pm and tell me when it is done." Cron-style scheduling means this now happens without you.

Inspect its memory: "Show me everything you have saved in memory and skills from today's session." Read it slowly - this is what house rule six looks like in practice. It saw your files; now its memory contains them.

Optional, after class: connect ONE messaging channel you actually use (Telegram is the gentlest) and message your agent from your phone. Same agent, same memory, new door.

★ Teaching the skillTurn what you just did into a reusable skill called weekly-notes-summary: summarize all markdown files in ~/hermes-course/notes into SUMMARY.md, overwriting the previous summary. Rules baked into the skill: never touch any other file, and if the folder has more than 40 files, stop and ask me first.
Real world

The Friday agent. One recurring job - "every Friday, digest this folder into one page" - is how most people find their agent groove: low stakes, high repetition, easy to verify. Get one job reliable, then add the second. The autonovel crowd started somewhere too.

Homework · the last one

Run it for a week ◐ one week, low stakes

  • Pick ONE low-stakes recurring job (notes summary, folder tidy-up, weekly reading digest) and let your agent own it for one full week on the schedule you set in Demo 2.
  • Keep a saves-vs-misses log: each run, one line - did it deliver, what did it get wrong, did it stay inside its rules. Seven lines of data beats any review you could read.
  • Re-read its memory at the end of the week. Anything in there you would not want on a stolen laptop? That is your cue to tighten what it sees.
  • If the week goes clean: widen one notch - a second job, or one new tool on the allowlist. One notch, not five.

Three questions before you graduate 🎯 ◐ 90 seconds

1 · Hermes Agent and the Hermes models - what is the relationship?

Same brand, different product: the agent is the machinery of autonomy (skills, memory, channels, scheduling) wrapped around any capable brain - 300+ via Portal, or your own local model.

2 · First run on your laptop tonight - which execution backend do you choose?

House rule 1: sandbox first. Start the agent in a container, earn trust task by task, and widen permissions deliberately - never by default.

3 · Why do agents need a much bigger context window than chat does?

The guide's phrase is "goes senile": an agent's working state lives in context. That is why 64K+ is recommended, and why our 14B (40,960 max) is an honest learning brain, not a production one.
