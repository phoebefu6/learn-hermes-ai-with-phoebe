Part 0

From "it runs" to "it runs right"

Anyone can type one command and get a chatbot. Running a local model WELL means three decisions: which quantization (how compressed), which runtime (Ollama or LM Studio), and how much context (memory of the conversation). Get those right and a 9GB file on a 16GB Mac feels like magic. Get them wrong and you get a slow, forgetful bot - and most people quit there. Not us.

Part 1 · covers the HF model cards + GGUF quant repos

Quantization without tears 6 min live

The full-precision Hermes 4 14B is far too big for a laptop. Quantization compresses the weights - the learned numbers - into fewer bits so the model fits in consumer RAM. It is a lossy trade: smaller files run lighter and faster but get a little dumber. Your whole job is picking the right rung on that ladder.

LiveWhat a GGUF quant actually is3 min▶

A model's weights are billions of high-precision numbers. GGUF is the standard file format for packing them into a single portable file, and quantization is the compression step: storing each weight in 2 to 8 bits instead of 16. The naming decodes simply:

  • The Q-number is bits per weight. Q4 stores weights in about 4 bits, Q8 in about 8. Fewer bits = smaller file = less RAM = faster tokens = slightly worse answers.
  • The suffix is the recipe. K_M means "K-quant, medium" - a smarter scheme that protects the most important weights. When in doubt, prefer _K_M variants.
  • File size roughly equals RAM appetite. A 9.0GB Q4_K_M wants about 9GB of memory for weights, plus headroom for context and the OS. That is the whole sizing game.

The community consensus, and ours: Q4_K_M is the sweet spot. Quality loss is minor for everyday work, and the savings buy you speed and headroom. Go higher only when RAM is abundant; go below Q3 only in emergencies.

Real world

The photo analogy. A RAW photo and a high-quality JPEG look identical on screen, but one is 60MB and one is 6MB. Q4_K_M is the high-quality JPEG of models: the compression is real, but you have to hunt for the artifacts. Q2 is the meme-quality repost - you can tell.

Self-studyMLX vs GGUF on Apple Silicon2 min read▶

GGUF is the universal format - it runs everywhere. But on a Mac there is a second option: MLX, Apple's own machine-learning framework, tuned for Apple Silicon's unified memory. The practical difference is speed: the MLX engine delivers roughly 2-3x the throughput of GGUF on the same Mac.

  • MLX builds of Hermes exist: mlx-community/Hermes-4-14B-4bit and -8bit are the 14B in MLX form (4bit is the Q4-equivalent).
  • LM Studio speaks both. It picks MLX automatically on a Mac when an MLX build exists. Ollama today is GGUF-only, so this is the main technical reason to also install LM Studio.
  • Quality is comparable at matching bit depths; the win is tokens per second, which you feel most in long reasoning chains (Session 4 foreshadowing).

Rule of thumb: Ollama + GGUF for scripting, automation, and the course's command-line spine; LM Studio + MLX when you want maximum interactive speed on a Mac.

Part 2 · covers the Ollama library and docs + LM Studio pages

Your rig: Ollama and LM Studio 6 min live

Two runtimes, one rule of trust. Ollama is the command-line workhorse you already have; LM Studio is the polished GUI with a speed advantage on Macs. The subtle part is WHERE the model comes from - and why the official path for Hermes 4 looks different from last week's one-liner.

LiveTwo pull paths - and why we prefer official repos3 min▶

Ollama can fetch models from two places, and the difference matters:

  • The Ollama library (ollama run hermes3:8b): curated, convenient, versioned tags. Hermes 3 lives here officially, with 3b/8b/70b/405b tags and tool-calling support.
  • Direct HuggingFace pull (ollama run hf.co/<repo>:<quant>): pulls a GGUF straight from any HuggingFace repo. This is the official path for Hermes 4, because there is no official hermes4 in the Ollama library.

You WILL find "hermes4" uploads in the Ollama library - they are community re-uploads with unverified provenance. Maybe fine, maybe stale, maybe misconfigured. The house rule: pull from repos owned by the source - NousResearch for official GGUFs, bartowski (the community's most trusted quantizer, linked from the Nous model cards) for the 14B ladder.

★ The two official pullsollama run hf.co/bartowski/NousResearch_Hermes-4-14B-GGUF:Q4_K_M ollama run hf.co/NousResearch/Hermes-4.3-36B-GGUF:Q4_K_M
Real world

The pharmacy rule. A data team pulled a popular community re-upload of a model and spent two days debugging weird outputs - the uploader had baked in a nonstandard chat template. Same weights from the official repo worked instantly. Model files are like medicine: the active ingredient matters, but so does who packaged it.

Self-studyLM Studio - the GUI route2 min read▶

LM Studio is a free desktop app that treats Hermes 4 as a first-class citizen - it has featured in the staff picks. Why keep it alongside Ollama:

  • Search "Hermes 4" in-app and it lists GGUF and MLX builds side by side, with a fits-your-RAM indicator before you download.
  • MLX engine on Apple Silicon: the 2-3x throughput win from Part 1, chosen automatically.
  • The reasoning toggle: Hermes 4 can think out loud before answering. LM Studio surfaces this as a simple on/off switch, plus a "keep CoT in subsequent turns" option. We flip that switch in anger in Session 4 - today you just get to find it.
  • Context sliders in the UI instead of Modelfiles - same physics as Part 3, friendlier dials. It advertises the full 131K max context for Hermes-4-70B if you have the RAM to feed it.

Ollama stays our spine because everything later (APIs, tools, agents) scripts against it. LM Studio is the cockpit view of the same machinery.

Part 3 · covers community context-window guidance

The context gotcha 4 min live

The number one community-documented local-AI failure is not speed and not quality - it is amnesia. Out of the box, Ollama gives models a small context window. Long chats silently scroll out of view and the model "goes senile": forgets your name, contradicts itself, loses the thread. The model was never broken. The window was.

LiveThe fix: num_ctx and the Modelfile4 min▶

The context window is a parameter, not a fact of life. Two ways to raise it in Ollama:

  • Environment variable: set OLLAMA_CONTEXT_LENGTH and every model gets the new default. Quick, blunt.
  • A Modelfile (our way): a tiny recipe file that bakes settings into a named model. Precise, per-model, and the foundation for everything we build later - Session 3 adds your persona to this exact file.
★ The Modelfile (save as "Modelfile", no extension)FROM hf.co/bartowski/NousResearch_Hermes-4-14B-GGUF:Q4_K_M PARAMETER num_ctx 16384 PARAMETER temperature 0.6

Then ollama create hermes4-14b-16k -f Modelfile builds your custom model, and ollama run hermes4-14b-16k runs it. The tradeoff is honest: context lives in RAM, so more window = more memory. 16K comfortably holds a long working session on 16GB; 32K and up is 32GB territory.

While we are in the file: temperature 0.6 is the official Nous sampling recommendation for Hermes 4, alongside top_p 0.95 and top_k 20. Session 3 explains what these dials actually do.

Spot the symptom If your local model ever starts ignoring instructions it followed an hour ago, do not blame the quant and do not re-pull. Check the context window first. It is the number one fix in every local-AI community for a reason.

Check your disk: you need ~9GB free. ollama list shows what you already have.

Pull and run the hero: ollama run hf.co/bartowski/NousResearch_Hermes-4-14B-GGUF:Q4_K_M - the download is ~9GB, so on venue wifi we watch Phoebe's pre-pulled copy and you run yours at home.

The Modelfile lab ★ 10 min · build your own

Now make it YOURS. You will build a named custom model - hero weights, 16K memory, official sampling - and verify the build like an engineer. This file is the seed of your assistant: Session 3 gives it a personality, Session 5 gives it output rules.

Make a folder for your assistant (say ~/hermes-lab) and create a file named Modelfile containing the three lines from Part 3: the FROM hf.co/... line, PARAMETER num_ctx 16384, PARAMETER temperature 0.6.

Build it: ollama create hermes4-14b-16k -f Modelfile. It reuses the weights you pulled in Demo 1 - no second download.

Verify like an engineer: ollama show hermes4-14b-16k. Confirm you see your context length and temperature in the output. Trust, but verify.

Run it: ollama run hermes4-14b-16k. Paste in a long document and ask questions about the START of it - the senility test your old setup would have failed.

Optional branch (Mac speed-lovers): install LM Studio, search "Hermes 4" in-app, load the 14B MLX build, and find the reasoning toggle in the chat sidebar. Do not ship it yet - that switch is Session 4's whole story.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · Going from Q8_0 down to Q4_K_M, what is the trade?

Quantization is lossy compression of the weights: fewer bits per weight = lighter and faster but a little dumber. Q4_K_M is the sweet spot where the loss is hard to notice and the savings are huge.

2 · Why do we pull Hermes 4 with an hf.co command instead of "ollama run hermes4"?

Hermes 3 is officially in the library; Hermes 4 is not. The trusted path is the source: NousResearch's own GGUF repo, or bartowski's quants linked from the Nous model cards.

3 · Your local model keeps forgetting things from earlier in a long chat. What does num_ctx 16384 fix?

The number one community-documented failure: the model only sees what fits in the window. Raising num_ctx (or OLLAMA_CONTEXT_LENGTH) keeps the whole conversation in view - at the cost of more RAM.
